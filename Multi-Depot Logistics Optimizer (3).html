Assumptions, complexity, demo workflow
  • Simulated travel (no road data): time = Euclidean km × 1.3 road factor ÷ speed × traffic multiplier. Matrix is computed on demand, not stored.
  • Clock starts 08:00 (minute 0). Service = 5 min. Early arrival waits for the window. Return to depot is billed only while stops remain pending. Capacity applies to a vehicle's pending load (one trip).
  • Cost = km × vehicle cost/km + 2 per late minute + 500 per unserved order (all configurable in C). Same model scores baseline and optimized. Both are heuristics, not provably optimal. Negative improvement is shown as-is.
  • Optimized: orders sorted by deadline → cheapest feasible insertion (vehicle, position; stock- and capacity-aware; +3 stability penalty for moving an order off its previous vehicle) → bounded 2-opt (≤5 passes). Complexity ≈ O(n·V·L²) insertion + O(5·V·L³) 2-opt, L = stops per route. Baseline: nearest feasible depot + nearest-neighbour, O(n·D log D + V·L²).
  • Rule-based optimization only; no machine learning or prediction. Replan keeps delivered orders, releases all unfinished ones and re-solves them (unaffected ones tend to stay due to the stability penalty).
  • Demo: 1 NORMAL → compare panel → 2 RUSH (see unserved + reasons) → 3 BREAKDOWN (before/after routes in vehicle table) → 4 SHORTAGE → 5 MULTIPLE → Add order live → Run self-tests.
